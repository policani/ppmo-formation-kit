# Portfolio Taxonomy

A PPMO needs a shared language before work can be compared, sequenced, or governed.

## Core taxonomy fields

| Field | Purpose | Example values |
|---|---|---|
| Portfolio lane | Groups work by operating domain | Technology, finance systems, operations, customer, data, compliance |
| Initiative type | Explains nature of work | Project, program, platform change, process change, regulatory, run-the-business |
| Lifecycle stage | Shows maturity | Idea, intake, discovery, business case, chartered, active, blocked, closing |
| Sponsor owner | Names accountable business owner | CIO, CFO, COO, CMO, business GM |
| Funding class | Separates commitment types | Funded, pending, discretionary, mandatory, unfunded mandate |
| Strategic theme | Connects to leadership intent | Growth, efficiency, compliance, resiliency, customer retention |
| Delivery model | Identifies execution path | Agile, waterfall, hybrid, vendor-led, operations-led |
| Risk class | Flags governance sensitivity | Low, moderate, high, regulated, security-sensitive |
| Readiness state | Shows whether review is possible | Ready, incomplete, blocked, duplicate, needs sponsor |

## Taxonomy rules

Keep categories few enough to use consistently. Do not create labels that imply approval. Separate business priority from delivery health. Separate mandatory work from discretionary work. Separate intake state from execution state. Mark unknowns visibly.

## Output

Produce taxonomy table, required baseline fields, optional fields, field definitions, example coded initiative list, data gaps and cleanup actions, and downstream fields for intake, scoring, reporting, and operations log.
