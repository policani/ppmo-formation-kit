# Handoff Rules

Use this file before finalizing the formation package.

## Downstream handoffs

| Output | Receiving module | Pass downstream | Do not pass downstream |
|---|---|---|---|
| Intake model | Portfolio Intake and Readiness Triage System | Entry channels, minimum fields, intake states, routing rules | Unapproved org design or implied funding authority |
| Taxonomy | Portfolio Intake and Readiness Triage System / Portfolio Prioritization Scoring Agent | Portfolio lanes, types, stages, sponsor fields, readiness states | Labels that imply priority without scoring |
| Decision-rights model | Executive Portfolio Review Pack Builder / PMO Governance Operations Log | Decision owners, forums, escalation paths | Unconfirmed authority assumptions as facts |
| Reporting model | Executive Portfolio Review Pack Builder | Views, cadence, decision signals, data gaps | Invented metrics or unverified baselines |
| Decision-log pattern | PMO Governance Operations Log | Decision fields, action owner fields, carry-forward rules | Private discussion notes not needed for governance |
| 30/60/90 plan | Human PPMO lead | Milestones, confirmations, pilots, handoffs | Claims that the PPMO is mature or fully operational |

## Handoff brief structure

Formation output, receiving module, purpose of handoff, confirmed inputs, open assumptions, privacy exclusions, human decisions still required, and suggested first prompt for receiving module.

## Non-overlap rule

This kit creates the operating container. Adjacent modules process work inside the container. Do not repeat their scoring, review-pack, or operating-log workflows here.
