# Operating Model

The PPMO Formation Kit is a formation-stage operating aid. It creates the minimum structure required for governed portfolio operation.

## Formation lifecycle

| Stage | Purpose | Output |
|---|---|---|
| 1. Diagnose | Understand why governance is needed now | Formation intake and operating problem |
| 2. Bound | Define what the PPMO owns and does not own | Operating charter |
| 3. Authorize | Clarify decision rights and escalation | Decision-rights model |
| 4. Classify | Establish common portfolio language | Portfolio taxonomy |
| 5. Intake | Define how demand enters governance | Intake model |
| 6. Govern | Design forums, cadence, inputs, and outputs | Governance council design |
| 7. Report | Define portfolio views and decision signals | Reporting model |
| 8. Mobilize | Move from design to operation | 30/60/90 plan |
| 9. Handoff | Route active work to adjacent systems | Handoff brief |

## Minimum viable PPMO

A minimum viable PPMO does not need every process, template, tool, and maturity model. It needs a clear reason to exist, sponsor agreement on scope, known decision rights, a usable taxonomy, consistent intake, a decision-producing cadence, reporting tied to tradeoffs, and a decision/action log.

## Formation principles

- Start with decisions, not templates.
- Separate intake, prioritization, execution, and review.
- Make authority visible before designing workflow.
- Classify work before comparing work.
- Keep reporting tied to actions, tradeoffs, and decisions.
- Treat weak evidence as a risk, not a fact.
- Build only enough process to create trust and follow-through.
